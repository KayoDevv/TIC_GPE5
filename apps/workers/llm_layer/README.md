# LLM Layer: LLM (The Semantic Analyst)

**Tech:** Python, specialized LLM model (e.g. Llama 3 8B self-hosted via vLLM or gRPC).

**Code Guidelines:** TDD (pytest-asyncio). Processing SLA: 3 to 5 seconds.

**Business Context:** "The Semantic Analyst". Correlates the initial email context with the technical results to determine the real intent.

**Responsibility:** Translate the technical logs into a clear human-readable summary for the non-technical user.

**Kafka Events (Consumed/Produced):**
- **Consumes:** `sandbox_layer.result` (must include both the technical report AND the email body context).
- **Produces:** `llm_layer.result` (binary decision Malicious/Clean + explanatory string).

## Technical Specifications
- **LLM Engine:** Local inference via `vLLM` (to optimize VRAM usage) or a remote gRPC server. The recommended model is Llama-3-8B-Instruct or equivalent, capable of being fine-tuned on cybersecurity.
- **Prompt Engineering:** Strict template. The prompt injects the business context (sender, subject, email body) and links it to the IOC JSON report (generated by the Sandbox Layer).
- **Asynchronous Processing:**
  1. Parsing and aggregation of the technical data from the Sandbox report.
  2. Asynchronous call to the LLM model with a very low temperature (e.g. `0.1` to `0.3`) to avoid hallucinations.
- **Output:** A clear binary decision as a boolean (`is_malicious`) and generation of an explanation text (`explanation_text`) understandable by a non-technical person (e.g. an SME's IT manager).
- **Performance Constraints:** Critical SLA of **3 to 5 seconds maximum** for the full generation of the explanation (requires a high token/sec LLM). A very low Time-To-First-Token (TTFT) is preferred.
